# 北辰 v2.9.3：对话完整性与流程修复

2026-10-11。本次完成重新验证、长对话与星图上下文、弹窗返回三项修复。

## 重新验证

验证按钮、回车和六位自动提交在判断本机有效会话之前绑定；重复初始化不重复绑定。有效会话回访后，云端失效重新显示星门时仍能正常输入。错误验证码不会清除原谈话；新验证码验证成功后，按既有产品约定开始新谈心，历次星图保留。30 秒换码、100 秒有效、一次使用、7 天会话、3 次星图额度继续保留。

## 完整原话与请求容量

- 短对话继续使用原始 user/assistant 角色。记录较多时，按时间顺序装入有角色标注的原文记录；只合并容器，不改写、概括或删除发言。最近的发言和系统指令保留原有角色及顺序。
- 星图同时携带学生原话和辰的实际提问，避免“是”“不是”“选第二个”失去含义。学生否定、犹豫、后来修正和家长期待分别保留；辰此前的推测不视为学生确认。
- 普通聊天、星图、格式修复和截断续写共用 `conversation-context.js`。长消息分成不超过 16000 字符的片段，Unicode 字符不从中间拆开。格式修复不再省略原报告中部。
- 云端默认总提示上限从 40000 调整至 100000 字符，HTTP 正文上限为 512 KiB；仍最多 24 条消息。首次请求预留 2 条和 20000 字符给续写；每次续写重新核对容量。`/healthz` 和 `/readyz` 返回实际 requestLimits，页面据此核对。字符预算不是 token 数，也不是无限上下文保证。
- 真的超限时明确提示并保留原话，不以删掉早期回答换取生成成功。不会新增每轮摘要模型调用，不降低原生思考强度或输出预算。

## 本机保存与刷新

移除原来的 40 条记录裁剪及星图完成后的单条纪要替换。可见对话与完整星图原文一直保留；未成功请求前的学生输入也立即保存。渲染报告时只显示前置回应，完整星图继续参与后续理解。

本机 localStorage 保留兼容存档，并使用独立 IndexedDB `beichen_conversations_v1` 备份当前完整谈话。刷新选择较新的副本，读取期间暂停发送，避免覆盖尚未恢复的原文；重新开始会按顺序清除两个副本，旧异步读取不会写回新谈话。两种保存均失败会提示保留当前页面。它不提供跨设备同步；清除浏览器数据会丢失本机记录。旧版已经裁剪掉的内容无法凭空恢复，但尚存的旧纪要仍兼容。

## 弹窗返回

使用 `window.history` 和独立 `overlay-navigation.js` 管理弹窗层级，不再误读对话数组 `history`。浏览器返回关闭相应层，关闭按钮与 Escape 消费对应记录；快速关闭／立即重开有顺序控制，前进和刷新不复活已关闭弹窗。必经的星门、序章和模式选择不加入可关闭层。

## 验证

本地 41 项检查中 39 项通过，2 项真实 Redis 检查交由 CI 的临时 Redis 验证。新增覆盖：早期排斥与后期修改意见、十份各 6000 字回答、超过旧 128 KiB 的中文 HTTP 正文、续写消息容量、长报告中部、emoji、完整本机存档、存储失败、重新验证、嵌套弹窗和快速关闭。语法检查和公开仓库凭据扫描通过。

隔离 localhost 页面实际完成首次验证、发送、刷新恢复、模拟云端失效、错误码保留谈话、重新验证，以及浏览器返回、关闭、前进和 Escape；没有使用正式验证码。

GPT-6 Sol/max 使用 32 轮虚构谈话及现行系统／星图指令实测。星图完整：5 张星卡、6 个专业均有推荐分析和就业方向、两个不同合法组合、156 字寄语；正文 1662 字符，流式正常结束。审阅确认保留“不喜欢生物、不想做医生”、爸爸希望学医、后来化学开窍、循迹机器人及成绩边界，未编造竞赛获奖和具体院校。星图后继续追问使用完整原话，正确区分学生和爸爸的意愿。两次上游调用沿用真实适配器的 max 参数；实测 221.8 秒和 10.5 秒，仅为本次样本耗时。
